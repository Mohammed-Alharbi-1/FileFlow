## CI and release automation

CI runs on Windows/Python 3.12 for main pushes, main PRs and manual dispatch.
Official checkout/setup/upload actions are pinned to verified commit SHAs.
Token access is read-only in tests, checkout does not persist credentials, and
no PR secrets or write permission are required. Static compile/privacy checks,
114 offscreen-compatible tests and eight actual-process headless cases are
configured. The native-tray desktop test is excluded by explicit name, not hidden
with continue-on-error. Hosted CI has not run because no GitHub remote exists.

Release automation requires a matching version tag, a finalized LICENSE, tests,
Windows PyInstaller build, expected EXE version/dependencies, smoke and headless
lifecycle checks, complete portable ZIP and SHA-256. Ordinary PRs cannot publish.
The publish job requires all three repository approval variables, a protected
`release` environment, and uses contents-write/actions-read only there. It creates
an owner-review **draft**, not an automatically public release. Configure required
reviewers and run native desktop tray checks before enabling these gates.
